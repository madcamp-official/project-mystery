# 장면별 주요 인물·NPC 배치 구현 Goal 프롬프트

## 사용 목적

이 문서는 `Under the Horizon`의 대사집과 장면·장소·인물 매트릭스를
Unity 런타임에 반영하기 위한 실행 프롬프트다.

새 Codex 작업에서 아래의 `Goal 프롬프트` 전체를 사용한다.

작업자는 엑셀의 논리적 동선과 게임 화면의 시각적 연출을 구분하되,
둘 중 어느 하나도 임의로 생략하지 않는다.

---

## Goal 프롬프트

### 목표

다음 두 엑셀을 단일 진실 원천으로 사용한다.

- `Under_the_Horizon_Dialogue_Complete_KR.xlsx`
- `Under_the_Horizon_Scene_Location_Character_Matrix_KR.xlsx`

41개 장면의 시간순 사건 상태와 25개 장소의 재실 정보를 Unity에 반영한다.

현재 장소에는 그 시점에 실제로 존재하는 주요 인물과 NPC만 표시한다.

배경에 표시된 인물을 직접 클릭하면 적절한 대화를 시작하게 한다.

하단의 획일적인 “승객 대화 가능” 버튼은 월드 인물 상호작용으로 대체한다.

캐릭터는 배경에 합성된 스티커가 아니라 그 공간에 서 있는 사람처럼 보여야 한다.

### 완료 조건

다음 조건을 모두 만족할 때만 goal을 완료 처리한다.

- 41개 장면이 빠짐없이 순서대로 등록되어 있다.
- 모든 장면에서 주요 인물 9명의 논리적 장소가 정의되어 있다.
- 모든 장소 코드는 25개 정규 장소 카탈로그와 일치한다.
- 현재 장면과 현재 장소에 맞는 인물만 배경에 표시된다.
- Adrian은 플레이어 시점과 월드 인물로 중복 표시되지 않는다.
- Daniel은 사망 이후 서 있는 NPC로 표시되지 않는다.
- Marcus의 부상 상태가 지정 구간에 유지된다.
- Evelyn의 구금 상태가 결말 장면에 유지된다.
- 장소별 NPC의 직군과 대사가 해당 공간의 기능에 맞는다.
- 주요 인물을 클릭하면 프로덕션 대화 또는 인물별 맥락 대화가 시작된다.
- 한 화면의 인물이 서로 겹치거나 주요 사물을 가리지 않는다.
- 발이 바닥면과 맞닿고 공중에 뜬 것처럼 보이지 않는다.
- 배경 사물 대비 인물의 크기와 원근이 자연스럽다.
- 배경 광원과 캐릭터의 색온도·노출·그림자가 조화를 이룬다.
- 지원 해상도에서 클릭 영역과 인물 배치가 유지된다.
- 자동화 테스트와 실제 PlayMode 검증 결과가 기록되어 있다.
- 기존 사용자 변경사항을 보존한다.
- 구현을 300~500줄 규모의 논리적 PR로 분리한다.
- 모든 PR은 Draft가 아닌 ready-to-merge 상태다.

### 입력 분석

먼저 두 엑셀의 시트, 행, 열, 수식, 병합 셀을 읽는다.

장면 ID를 정규화한다.

장면의 시간, 챕터, 사건 상태, 중심 장소를 추출한다.

각 주요 인물의 장면별 장소를 추출한다.

장소별 NPC 직군, 등장 이유, 대사, 감정 태그를 추출한다.

대사집에서 장면별 발화자와 대화 시작 조건을 추출한다.

같은 장면 ID가 두 문서에서 서로 다른 의미로 쓰이면 충돌 목록을 만든다.

충돌은 다음 우선순위로 해결한다.

1. 살인, 부상, 구금처럼 되돌릴 수 없는 사건 상태
2. 대사집의 명시적인 장면 지문
3. 장면·장소·인물 매트릭스의 위치
4. 제작 코드에 이미 존재하는 정규 장면 정의
5. 위 기준으로도 결정할 수 없을 때만 사용자 확인

### 시간순 상태 규칙

장면 정렬은 문자열 정렬이 아니라 엑셀에 기록된 이야기 순서를 사용한다.

프롤로그 `P-01`부터 에필로그 `D8-03`까지 연속된 순서를 보존한다.

현재 장면은 다음 순서로 해석한다.

1. 실행 중인 프로덕션 대화 장면
2. 저장된 체크포인트 장면
3. 현재 시작 가능한 다음 장면
4. 가장 최근 완료 장면

이전 장면의 인물이 다음 장면에 자동으로 남아 있으면 안 된다.

미래 장면의 인물이 현재 장소에 미리 나타나면 안 된다.

Daniel의 사망 시점 이후에는 상태를 `Deceased`로 유지한다.

사망자의 논리적 위치는 사건·운구 기록을 위해 남길 수 있다.

하지만 일반적인 클릭형 직립 캐릭터로 생성하지 않는다.

Marcus의 부상 구간에는 `Injured` 상태와 부상 대사를 사용한다.

회복 장면 이후에는 정상 상태로 명시적으로 복귀한다.

Evelyn의 체포 이후에는 `Detained` 상태와 구금 대사를 사용한다.

구금 상태의 캐릭터는 자유로운 승객처럼 연출하지 않는다.

### 논리적 재실과 화면 표시

엑셀의 재실 정보는 논리적 사실이다.

화면 표시 수는 가독성과 배경 보존을 위한 연출 예산이다.

두 정보를 같은 배열에서 삭제 방식으로 처리하지 않는다.

모든 재실 인물은 논리 카탈로그에 보존한다.

전경에 표시하지 못한 인물은 `OffCamera`로 표현한다.

`OffCamera`는 “그 장소에 없음”을 뜻하지 않는다.

화면 기본 예산은 전신 인물 1~4명이며 기본 권장값은 장소 NPC 한 명과 주요 인물
두 명, 총 세 명이다.

군중 장면도 인물을 작게 줄여 모두 밀어 넣지 않는다.

장면별 발화 중요도에 따라 전경 우선순위를 정한다.

플레이어인 Adrian은 전경 후보에서 제외한다.

사망 상태의 Daniel은 전경 후보에서 제외한다.

부상과 구금 상태의 인물은 제외하지 말고 상태를 시각·대사에 반영한다.

### 주요 인물 우선순위

장면의 실제 대사 발화자를 먼저 표시한다.

사건의 직접 목격자나 질문 대상자를 다음으로 표시한다.

사건 상태가 변하는 인물을 다음으로 표시한다.

그 뒤에는 엑셀의 주요 인물 순서를 안정적인 폴백으로 사용한다.

우선순위는 장면 ID별 데이터로 관리한다.

코드의 조건문에 장면별 예외를 흩어 놓지 않는다.

같은 우선순위를 여러 시스템이 필요로 하면 카탈로그를 공유한다.

### 장소별 NPC 규칙

NPC는 해당 장소의 기능과 직무에 맞아야 한다.

항구에는 부두 하역원이나 승선 담당자를 사용한다.

갱웨이에는 승선 보안과 안내 직군을 사용한다.

객실에는 객실 승무원이나 해당 객실 관계자를 사용한다.

라운지에는 호스트, 승객, 음악가처럼 공개 공간에 맞는 직군을 사용한다.

식당에는 소믈리에나 식음 승무원을 사용한다.

보안실에는 보안 운용 담당자를 사용한다.

기관 구역에는 엔지니어, 제어 담당자, 정비 기술자를 사용한다.

의무실에는 의료진과 환자 맥락의 인물을 사용한다.

세탁실에는 세탁 감독이나 서비스 승무원을 사용한다.

기록 보관소에는 기록 담당자를 사용한다.

같은 범용 승객을 모든 장소에 반복 배치하지 않는다.

한 NPC가 동시에 여러 장소에 있는 것처럼 보이지 않게 한다.

직군 자산이 부족하면 기존 화풍에 맞는 신규 컷아웃을 생성한다.

새 자산은 역할이 겹치지 않도록 명확한 식별자를 사용한다.

### 대사 규칙

장소 NPC 대사는 장면 ID와 장소 코드를 함께 조건으로 사용한다.

장면이 다르면 같은 장소에서도 사건 진행에 맞는 대사를 선택한다.

미래 사건을 암시하는 대사가 이전 장면에서 노출되면 안 된다.

이미 해결된 사건을 미해결 상태처럼 말하면 안 된다.

NPC는 자신의 직무상 알 수 없는 비밀을 단정하지 않는다.

목격 정보와 추측을 구분한다.

주요 인물의 핵심 장면 클릭은 해당 프로덕션 대화를 시작한다.

핵심 장면이 아닌 클릭은 인물별 짧은 맥락 대사를 사용한다.

짧은 대사도 인물의 역할과 현재 상태가 드러나야 한다.

부상 상태는 통증과 대화 가능 범위를 반영한다.

구금 상태는 경비 감시와 정식 심문 맥락을 반영한다.

대사를 새로 만들 때 기존 반전이나 범인 정보를 누설하지 않는다.

대사 수정은 원본 엑셀과 런타임 카탈로그의 대응 관계를 기록한다.

### 캐릭터 자산 규칙

주요 인물은 인물별 독립 투명 PNG를 사용한다.

전신이 잘리지 않아야 한다.

발끝과 머리 위에 보정 가능한 투명 여백을 남긴다.

투명 배경 가장자리에 녹색이나 흰색 테두리가 남지 않아야 한다.

기존 초상화와 얼굴, 복장, 소품, 시대감이 일치해야 한다.

같은 캐릭터를 장소마다 다른 사람처럼 재생성하지 않는다.

배경 NPC는 직군별로 구분 가능한 실루엣과 소품을 사용한다.

Unity 임포트 설정은 알파와 고해상도 UI 표시를 보존한다.

리소스 경로와 Unity `.meta` 파일을 함께 커밋한다.

### 발 접지

RectTransform의 피벗은 발 기준 하단 중앙을 사용한다.

PNG 전체 하단이 아니라 실제 불투명 픽셀의 발끝을 계산한다.

자산별 `VisibleBottomMargin`을 카탈로그에 저장한다.

배치 계산은 투명 여백을 제외한 가시 영역을 기준으로 한다.

발 아래 그림자는 같은 바닥 앵커를 사용한다.

그림자가 발보다 위에 있거나 멀리 분리되면 실패로 간주한다.

배경의 계단, 책상, 카트 위에 잘못 서지 않도록 안전 앵커를 사용한다.

세탁실처럼 전경 카트가 있는 장소는 카트 뒤나 옆 바닥면을 선택한다.

작업실처럼 큰 책상이 있는 장소는 책상 위가 아니라 통로에 배치한다.

### 원근과 크기

배경의 문, 난간, 책상, 기계 높이를 인간 스케일 기준으로 사용한다.

캐릭터의 머리 높이와 배경 소실점을 함께 확인한다.

전경에 가까운 인물은 더 크게, 후경 인물은 더 작게 표시한다.

화면을 채우기 위해 발 접지를 깨뜨리는 방식으로 확대하지 않는다.

가로 종횡비는 원본 자산 비율을 유지한다.

주요 인물이 일반 배경 NPC보다 지나치게 작지 않도록 기준 배율을 둔다.

1280×720에서도 얼굴과 클릭 실루엣을 알아볼 수 있어야 한다.

인물 셋을 모두 보여주기 위해 비현실적으로 축소하지 않는다.

### 가림과 배치

배경의 핵심 단서, 출입구, 조작 패널을 가리지 않는다.

좌상단 문맥, 상단 목표, 우상단 전역 기능, 하단 읽기 영역과 우하단 주요 행동의
Safe Area를 가리지 않는다.

특히 인물의 얼굴과 발이 UI 패널 뒤에 들어가지 않게 한다.

인물끼리 얼굴이나 몸통이 겹치지 않는다.

클릭 영역이 다른 인물의 클릭 영역과 과도하게 겹치지 않는다.

단일 인물 장면은 장소별 수동 구도를 우선한다.

복수 인물 장면은 검증된 좌·중앙·우 안전 슬롯을 사용한다.

장소별 안전 슬롯이 부족하면 새 슬롯을 데이터로 추가한다.

런타임에서 임의 난수로 위치를 바꾸지 않는다.

같은 장면과 해상도에서는 항상 같은 구도를 재현한다.

### 조명과 배경 화풍

장소별 색온도 카탈로그를 사용한다.

공개 갑판과 항구는 자연광 계열을 사용한다.

고급 객실과 라운지는 따뜻한 실내광을 사용한다.

기관실과 발전기는 호박색 기계광을 사용한다.

보안실과 서비스 레일은 차가운 기계광을 사용한다.

의무실과 기록 구역은 중성 실내광을 사용한다.

캐릭터에 색조만 덧씌우고 끝내지 않는다.

채도, 노출, 대비, 가장자리 부드러움을 함께 조정한다.

배경 광원의 방향과 캐릭터 실루엣 그림자 방향을 일치시킨다.

바닥 그림자의 크기는 인물 크기와 원근에 비례한다.

배경이 어두우면 캐릭터만 과도하게 밝게 뜨지 않게 한다.

배경이 밝으면 검은 외곽선이 스티커처럼 두드러지지 않게 한다.

### 상호작용

인물 전체 실루엣을 클릭 대상으로 사용한다.

투명 영역만 클릭되는 큰 사각형을 피한다.

별도 하단 대화 버튼을 인물 클릭과 중복 제공하지 않는다.

기본 탐색 상태에서는 이름표, 클릭 포인트와 윤곽선을 숨긴다.

마우스 호버, 키보드·게임패드 포커스와 접근성 탐색 모드에서만 대상 윤곽과
자연어 이름을 표시한다.

클릭 시 인물 이름과 적절한 대화가 표시되어야 한다.

핵심 대화는 진행 가능 여부를 확인한 뒤 시작한다.

아직 열리지 않은 미래 장면을 클릭으로 시작하면 안 된다.

진행 중인 대화를 중복 시작하면 안 된다.

상호작용이 불가능한 상태라면 시각 피드백을 제공한다.

마우스, 터치, 컨트롤러 입력에서 같은 논리를 공유한다.

### 탐색과 대화 표시 전환

탐색 중에는 장소 원근과 바닥선에 맞춘 전신을 표시한다.

대화를 시작하면 현재 대화 프레젠테이션에 필요한 화자 초상 또는 강조 전신을
표시하고, 배경 전신과 중복되어 같은 인물이 두 명처럼 보이지 않게 한다.

대화 종료 시 탐색 전신의 위치, 크기, 조명, 클릭 가능 상태와 포커스를 복원한다.

대화 기록이나 조사 기록 오버레이를 닫을 때도 같은 탐색 카메라와 인물 배치를
복원한다.

초상 자산만 있고 전신 자산이 없을 때 초상을 억지로 확대해 월드 인물처럼
사용하지 않는다.

필요한 전신 자산을 제작하거나 검증된 폴백 전신을 사용한다.

### 데이터 구조

`ScenePresenceCatalog`는 41개 장면의 논리적 재실을 소유한다.

`ScenePresencePresentationPolicy`는 전경 표시 후보를 선택한다.

`SceneContextBarkCatalog`는 장면·장소별 NPC 대사를 소유한다.

`AmbientWorldCharacterCatalog`는 자산 경로와 투명 여백을 소유한다.

`AmbientWorldStageCatalog`는 장소별 위치·조명·그림자를 소유한다.

UI 컨트롤러는 위 카탈로그의 데이터를 소비한다.

UI 컨트롤러에 장면별 하드코딩을 새로 추가하지 않는다.

### PR 분할

첫 PR은 장면별 논리 동선 카탈로그와 상태 전이를 추가한다.

둘째 PR은 장면·장소별 NPC 대사 선택을 추가한다.

셋째 PR은 주요 인물 월드 자산과 전경 표시 정책을 추가한다.

넷째 PR은 실제 클릭형 배치와 장소별 시각 보정을 연결한다.

다섯째 PR은 goal 문서와 운영·검증 기준을 추가한다.

각 PR의 코드 변경은 가능한 한 300~500줄로 유지한다.

이미지 바이너리와 Unity 메타데이터는 코드 줄 수에서 분리해 설명한다.

앞 PR의 자동 병합을 기다리지 않는다.

각 브랜치는 앞선 변경을 포함하는 스택형 브랜치로 만들 수 있다.

모든 PR은 Draft가 아닌 ready-to-merge 상태로 연다.

PR 본문에는 의존 PR과 검토 순서를 명시한다.

### 커밋과 PR 메시지

커밋 메시지는 한국어 Conventional Commit 형식을 사용한다.

예시는 다음과 같다.

- `feat: 장면별 주요 인물 동선 카탈로그 추가`
- `feat: 장면별 NPC 맥락 대사 선택`
- `feat: 주요 인물 월드 컷아웃과 표시 정책 추가`
- `feat: 장면 동선에 맞는 클릭형 주요 인물 배치`
- `fix: 세탁실 인물의 발 접지와 원근 보정`
- `fix: 기관실 캐릭터 조명과 그림자 방향 일치`
- `docs: 장면별 인물 배치 구현 goal 문서화`

`fix(dialogue): persist production scene progress`처럼
영문 설명이나 괄호형 스코프를 사용하지 않는다.

- 목적과 사용자에게 보이는 변화
- 엑셀에서 반영한 논리
- 주요 파일과 책임
- 사망·부상·구금 처리
- 발 접지·원근·가림·조명 처리
- 대사 선택과 미래 정보 누출 방지
- 자동화 및 수동 검증 결과
- 알려진 기존 실패
- 변경 줄 수
- 사용자 변경사항 보존 여부
- 다음 스택 PR의 범위

### 작업 트리 안전

작업 전 `git status`로 사용자 변경을 식별한다.

사용자가 수정한 파일은 관련 작업이 아니면 건드리지 않는다.

`project-mystery.slnx` 같은 IDE 생성 변경은 자동으로 포함하지 않는다.

분석용 `tmp/`와 출력용 `outputs/`는 커밋하지 않는다.

명시적인 파일 목록만 `git add`한다.

파괴적인 reset이나 checkout으로 사용자 변경을 지우지 않는다.

각 커밋 전 staged diff를 다시 확인한다.

각 push 후 원격 브랜치와 PR 상태를 확인한다.

### 최종 보고

생성한 모든 ready PR의 번호와 URL을 순서대로 제공한다.

각 PR의 책임과 변경량을 한 줄로 요약한다.

테스트 통과 수와 기존 실패를 구분해 보고한다.

새로 생성한 캐릭터 자산 경로를 제공한다.

보존한 사용자 변경사항을 명시한다.

아직 필요한 실제 화면 검증이 있다면 숨기지 않고 적는다.

goal이 완전히 달성되기 전에는 완료로 표시하지 않는다.

## 금지 사항

- 모든 장소에 같은 승객을 반복 배치하지 않는다.
- 장면 ID 없이 장소만으로 대사를 고르지 않는다.
- 미래 사건의 대사를 이전 장면에 노출하지 않는다.
- 사망자를 일반 직립 캐릭터로 표시하지 않는다.
- 캐릭터 발을 투명 이미지 하단에 단순 정렬하지 않는다.
- 배경 사물을 무시하고 화면 좌우 끝에 기계적으로 배치하지 않는다.
- 인물을 모두 보여주기 위해 비현실적으로 축소하지 않는다.
- 조명 보정 없이 밝은 원본 컷아웃을 그대로 합성하지 않는다.
- 신규 인물을 기존 캐릭터와 다른 화풍으로 생성하지 않는다.
- 클릭형 인물과 하단 대화 버튼을 중복 제공하지 않는다.
- 테스트 실패를 관련 여부 분석 없이 무시하지 않는다.
- 사용자 변경 파일을 편의를 위해 초기화하지 않는다.
- 앞 PR 병합을 기다리느라 다음 ready PR 생성을 중단하지 않는다.
