이 계획에서 “기획서 내용을 줄이지 않는다”는 다음과 같이 해석한다.

1. GDD의 확정, 권장, Must, Should, Could, Cut First 항목을 모두 출시 백로그에 유지한다.
2. GDD의 `Cut First`는 원문의 위험 대응 우선순위를 기록한 것이며, 이 계획에서는 자동 감축 권한으로 사용하지 않는다.
3. 일정이 밀리면 범위를 삭제하지 않고 일정 연장, 제작 방식 단순화, 라이선스 에셋 활용, 외부 납품 활용 중 하나로 해결한다.
4. 본 문서는 GDD를 대체하지 않는다. 원문 48페이지가 서사와 콘텐츠의 최종 기준이며, 본 문서는 각 항목을 구현·검증 작업으로 연결한다.
5. 좌석 배치와 퍼즐 시간은 원문 권고대로 Vertical Slice 결과에 따라 조정할 수 있지만, 퍼즐·단서·캐릭터·챕터 자체는 제거하지 않는다.

## 1. 실행 결론

### 1.1 프로젝트 기준선

- 로그라인: “잠긴 화장실에서 발견된 시신. 유일한 단서는 존재하지 않는 좌석, 0A.”
- 핵심 소품 표기: `NIGHTJAR AIRLINES / FLIGHT 709`, `PASSENGER A. VALE`, `SEAT 0A`, `THIS SEAT DOES NOT EXIST.`
- 장르: 2D 포인트앤클릭 추리 어드벤처.
- 제목: `SEAT 0A`.
- 플레이타임: 첫 플레이, 표준 힌트 기준 150-180분.
- 구성: 프롤로그 + Chapter 1-4 + 에필로그.
- 주요 무대: Meridian International Airport / Nightjar Airlines Flight 709.
- 기체: 단일 통로형 3-3 배열, 24열, 1-4열 프리미엄, 5-24열 일반석, 전방 갤리와 전방 화장실. 후방 화장실은 배경으로만 사용.
- 핵심 시스템: 현장 조사, 증거 확대, 심문, 사건 수첩, Cabin Timeline, Final Deduction.
- 핵심 퍼즐: 7개.
- 주요 캐릭터: 8명.
- 결말: 선형 결론 1개 + 짧은 에필로그. 추리 정확도와 선택 조사량에 따른 대사 변형은 유지한다.
- 실패: 게임오버 없음. 잘못된 증거는 짧은 반응 뒤 즉시 재시도하고 페널티를 주지 않는다.
- 필수 단서: 장면 종료 직전에 누락을 자연스럽게 확인하여 소프트락을 방지한다.
- 음성: 오프닝, 발견, 핵심 모순, 최종 심문, 에필로그 중심의 25-35분 부분 음성.
- 플랫폼: PC 우선, 키보드/마우스와 XInput 패드 동시 지원. 터치 확장을 고려한다.

### 1.2 엔진과 기술 기준

- 엔진은 `Unity 6.3 LTS`로 고정한다. Unity는 6.3 LTS를 2027년 12월까지 지원한다고 안내하며, 특정 버전에 제작을 고정하려는 팀에 LTS를 권장한다. 기준일에 확인 가능한 패치는 `6000.3.19f1`(2026-07-01)이며, 프로젝트 생성 시 이 버전 또는 그 이후의 검증된 6.3 LTS 패치를 전원이 동일하게 설치한다.  
  참고: [Unity 6 릴리스 지원](https://unity.com/kr/releases/unity-6/support), [Unity 6000.3.19f1 릴리스](https://unity.com/releases/editor/whats-new/6000.3.19f1)
- 렌더링: 2D URP. 페인팅 배경, 2D 캐릭터, 제한 애니메이션, 2D 조명/전체 화면 오버레이를 사용한다.
- 런타임 UI: uGUI + TextMeshPro. 드래그, 포커스, 패드 내비게이션, 160% 자막 검증을 같은 프리팹에서 수행한다.
- 입력: Unity Input System. Unity는 새 Input System을 대부분의 프로젝트에 권장한다.  
  참고: [Unity Input 문서](https://docs.unity3d.com/6000.0/Documentation/Manual/Input.html)
- 현지화: Unity Localization. 한국어를 원문 로케일, 영어를 번역 로케일로 두고 의사 현지화를 알파 이전부터 실행한다.  
  참고: [Unity Localization 패키지](https://docs.unity3d.com/6000.0/Documentation/Manual/com.unity.localization.html)
- 에셋 로딩: Addressables의 로컬 카탈로그만 사용한다. 온라인 콘텐츠는 두지 않으며, 장면/대형 배경/음성의 비동기 로딩과 메모리 해제를 위해 사용한다.  
  참고: [Unity Addressables 개요](https://docs.unity3d.com/2023.2/Documentation/Manual/com.unity.addressables.html)
- 저장: 버전이 있는 JSON 세이브 + 원자적 파일 교체 + 백업. Unity 오브젝트 참조가 아니라 안정적인 문자열 ID를 저장한다.
- 테스트: 순수 C# 도메인 테스트, Unity EditMode 테스트, PlayMode 스모크 테스트, 콘텐츠 그래프 검증기를 함께 사용한다.

### 1.3 3인 일정의 현실성

원문 일정은 4-6명, 7-9개월, 총 29-36인월을 가정한다. 3명이 32주 일하면 총 24인월에 불과하므로 같은 범위를 32주에 끝내는 계획은 채택하지 않는다.

- 3명 x 52주 = 총 156인주.
- 회의, 리뷰, 휴가, 빌드 대응 등 15%를 제외하면 약 132.6 생산 인주다.
- 이는 원문의 29-36인월 중 약 33인월에 해당해 전체 범위를 유지할 수 있는 최소 현실선이다.
- 44주 스트레치 목표는 음성·음악·영문 번역·후반 QA를 고정가 외부 납품으로 처리하고, Vertical Slice에서 재작업이 거의 없을 때만 사용한다.
- 세 명이 파트타임이거나 Unity/2D 아트/내러티브 중 한 축이 초급이면 8-12주를 추가한다.

## 3. 바이브 코딩 규칙

### 3.1 AI에 맡길 작업

- 반복적인 ScriptableObject/JSON 스키마, 에디터 임포터, 검증기, 테스트 뼈대.
- 요구사항이 명시된 단일 상태 전이, UI 바인딩, 퍼즐의 순수 판정 로직.
- 대사 CSV의 키 생성, 누락 검사, 길이 검사, 용어집 일관성 검사.
- Save migration, 콘텐츠 그래프 순회, 도달 가능성 테스트, 빌드 로그 분류.
- 임시 UI/임시 아트/플레이스홀더 제작과 변형안 비교.

### 3.2 사람이 직접 결정할 작업

- 사건 논리, 범인 노출 속도, 인물의 감정선, 최종 대사.
- 공개 API, 저장 포맷, 씬 구조, 패키지 추가/업그레이드.
- AI 산출물의 라이선스와 출처 판단.
- 항공 절차의 사실성, 범행 장치의 안전한 추상화 수준.
- 플레이테스트 결과에 따른 난이도와 힌트 타이밍.

### 3.3 프롬프트 계약

모든 코드 작업 프롬프트에는 아래 여섯 항목을 넣는다.

1. 연결된 GDD 페이지와 요구사항 ID.
2. 변경 가능한 파일 목록.
3. 변경 금지 영역과 비목표.
4. 입력, 출력, 상태 전이.
5. 실패·저장·접근성 조건.
6. 실행해야 할 테스트와 완료 기준.

AI가 요구사항에 없는 서사 사실, 단서, 좌석, 시간, 인물 관계를 만들면 폐기한다. 새 제안은 코드가 아니라 `Decision Proposal`로 제출한다.

### 3.4 변경 크기와 브랜치

- `main`은 항상 컴파일되고 처음부터 엔딩까지의 현재 범위가 실행되어야 한다.
- 브랜치: `feat/REQ-ID-short-name`, `fix/BUG-ID-short-name`.
- PR 하나는 원칙적으로 한 요구사항, 한 상태 머신, 또는 한 UI 화면만 다룬다.
- Unity YAML 충돌을 피하기 위해 한 주 동안 씬/프리팹별 단일 소유자를 지정한다.
- 대형 바이너리는 Git LFS를 사용한다. `.psd`, `.kra`, `.wav`, `.flac`, `.mp4`, 고해상도 원본을 포함한다.
- `Visible Meta Files`, `Force Text`, UnityYAMLMerge를 프로젝트 시작일에 고정한다.
- AI가 생성한 코드는 작성자와 별개의 사람이 리뷰하고, 컴파일 성공만으로 병합하지 않는다.

### 3.5 Definition of Ready

작업을 시작하려면 다음이 모두 있어야 한다.

- GDD 페이지/요구사항 ID.
- 사용자 관점의 완료 문장.
- 필요한 데이터 ID, 선행 플래그, 출력 플래그.
- 정상 경로와 최소 1개 실패 경로.
- 저장/로드 시 기대 상태.
- 키보드/패드 요구.
- 관련 아트/오디오가 없을 때 사용할 플레이스홀더.

### 3.6 Definition of Done

- 인수 기준을 수동 또는 자동 테스트로 통과했다.
- 새 데이터가 콘텐츠 검증기를 통과했다.
- 중간 저장 후 재개와 챕터 체크포인트에서 동일하게 동작한다.
- 키보드/마우스와 XInput 패드로 완료할 수 있다.
- 한국어와 의사 영어에서 UI가 잘리지 않는다.
- 필수 자막, 색상 외 아이콘/패턴, 힌트 단계가 반영됐다.
- 관련 GDD 추적표 상태가 `Implemented`로 바뀌었다.
- 주간 Windows 빌드에서 회귀가 없다.

### 4.2 씬 전략

- `00_Bootstrap`: GameState, SaveService, AudioService, LocalizationService, InputRouter, SceneFlow를 유지한다.
- UI는 별도 영속 씬으로 두고 탐색/대화/수첩/퍼즐 화면을 상태에 따라 전환한다.
- 공항과 기내 장소는 작은 additive scene 또는 Addressable prefab 단위로 로드한다.
- 장소 하나에 모든 상태를 복제하지 않는다. 기본 배경 + 캐릭터 포즈 + 카트/선반/조명 오버레이로 12-16개 상태 변형을 만든다.
- 씬 파일에는 콘텐츠 로직을 넣지 않는다. 장면 상태는 `scene_id`와 데이터에서 재구성한다.

### 4.3 핵심 데이터

| 데이터 | 필수 필드 | 런타임 책임 |
|---|---|---|
| SceneDefinition | `scene_id`, states, hotspots, characters, exits | 상태별 배경/핫스폿/인물 교체, 빠른 이동 |
| HotspotDefinition | `hotspot_id`, state variants, condition, result | 관찰문, 증거/주제 획득, 최초 강조 |
| CharacterDefinition | `character_id`, seat, portraits, poses, topics | 현재 감정, 대화 가능 상태, 위치 |
| DialogueGraph | `node_id`, speaker, line_id, condition, result, contradiction` | 주제형 대화, 문장 카드, 증거 제시 |
| EvidenceDefinition | `evidence_id`, views, inspect_points, tags, links | 확대/회전/앞뒤, 심층 정보, 결론 연결 |
| PuzzleDefinition | `puzzle_id`, entry, steps, outputs, hints, save_state` | 진입 이유, 단계 판정, 결과와 힌트 |
| TimelineDefinition | `timepoint`, entities, constraint, evidence_ref` | 배치 검증, 충돌 설명, 난이도별 피드백 |
| QuestionDefinition | `question_id`, answer, evidence_groups, unlock` | Final Deduction 순차 해금과 증거 2슬롯 |
| GameState | flags, evidence, dialogue, puzzle, scene, settings | 저장 가능한 단일 진행 상태 |
| LocalizedLine | `line_id`, locale, speaker, text, voice_id` | 한국어/영어, 자막, 부분 음성 매칭 |

ScriptableObject는 정적 정의만 담고, 플레이 중 변하는 상태는 별도 직렬화 가능한 `GameState`에 둔다. 저장 데이터에 Unity GUID나 오브젝트 참조를 직접 넣지 않는다.

### 4.4 콘텐츠 검증기

에디터 메뉴와 CI에서 아래를 한 번에 검사한다.

- 중복/누락 ID.
- 존재하지 않는 장면, 캐릭터, 증거, 대사, 음성 참조.
- 필수 증거 E01-E16의 획득 경로와 심층 조사 경로.
- 조건-결과 그래프의 순환 잠금과 도달 불가능 노드.
- 각 최종 결론에 서로 다른 범주의 증거가 최소 2개 있는지.
- PZ-07 진입 전 E02, E11, E12, 6개 이상 진술, 패널 장치 가설이 도달 가능한지.
- 모든 대사에 KO/EN 키가 있고, 부분 음성 대상에 `voice_id`가 있는지.
- 한 화면 대화 주제 4개 이하, 현재 질문 2-4개.
- 한국어 대사 한 페이지 42-58자 권장, 최대 3줄.
- 저장 트리거가 없는 필수 상태 전이.
- 엔딩까지의 Golden Path와 각 챕터 시작 체크포인트의 도달 가능성.

## 5. 시스템 구현 계획

### 5.1 탐색과 장면 상태

구현 범위:

- 각 배경에 기본 핫스폿 6-10개, 필수 2-3개, 선택 반응 3-5개.
- `HotspotState`: `unseen / seen / evidence_collected / updated`.
- 사건 전/후처럼 같은 핫스폿의 문장과 결과가 상태에 따라 바뀐다.
- 장소 인물은 2-3개의 포즈 위치를 바꾸어 정적인 느낌을 줄인다.
- 새 정보가 있는 핫스폿은 최초 1회만 미세한 포커스 또는 환경음으로 강조한다.
- 필수 핫스폿을 못 찾고 다른 대화를 소진하면 환경음, 시선, 반짝임을 사용한다.
- 장면을 떠날 수는 있지만 챕터 종료 직전 Noah가 누락된 필수 항목을 상기시킨다.

원문 상태 키 예시는 그대로 테스트 픽스처로 둔다.

- `SceneState`: `airport_gate_before_bag`, `airport_gate_after_bag`, `cabin_after_murder`.
- `HotspotState`: `unseen`, `seen`, `evidence_collected`, `updated`.
- `CharacterState`: `available_topics`, `current_emotion`, `contradiction_unlocked`.
- `GlobalFlags`: `seat_changed`, `ruby_footage_deleted`, `lavatory_opened`, `preinstall_hypothesis`.

인수 기준:

- 장면을 나갔다 돌아와도 최신 인물 위치와 핫스폿 상태가 유지된다.
- 필수 단서가 없는 상태에서 챕터 완료를 누르면 누락 항목의 위치를 직접 말하지 않고 자연스럽게 조사로 돌려보낸다.
- 모든 상호작용은 증거, 대화 주제, 상태 문장, 장소 해금 중 하나를 바꾼다.

### 5.2 대화와 Present Evidence

구현 범위:

- 인물별 대화 주제 2-3개, 한 화면 최대 4개.
- 중요한 문장은 짧은 정지 뒤 문장 카드로 분리한다.
- 특정 증거를 획득해야 모순 문장이 선택 가능해진다.
- 모순 선택 시 관련 증거를 먼저 필터링하지만 전체 목록도 열 수 있다.
- 정답 반응은 표정 변화 -> 짧은 침묵 -> 새로운 사실 순서다.
- 한 심문은 6-10분, 최대 증거 제시 2회와 선택 대화 1회.
- 잘못된 증거는 캐릭터별 짧은 반응 뒤 즉시 재선택하고 페널티가 없다.
- 같은 심문을 다른 순서로 진행해도 후속 주제가 정상 해금된다.

Marcus 2차 예시를 테스트 픽스처로 둔다.

- 진술: “탑승 전에는 정비 구역에만 있었습니다. 전방 객실에는 들어간 적이 없어요.”
- 모순: “전방 객실에는 들어간 적이 없다.”
- 정답: E03 또는 E14.
- 출력: Marcus가 “갤리 점검만 했다”고 진술을 수정해 패널 접근 가능성을 인정한다.

### 5.3 Evidence Inspection

구현 범위:

- 중앙 오브젝트, 확대/축소, 360도 회전 또는 앞/뒤 전환, 조사 포인트.
- 모든 필수 증거는 최소 1개 표면 정보와 1개 심층 정보를 가진다.
- 회전은 드래그와 버튼을 모두 지원한다.
- 조사 완료도와 관련 인물/결론을 사건 수첩에 표시한다.

대표 심층 정보:

| 증거 | 표면 정보 | 심층 조사 |
|---|---|---|
| 0A 탑승권 | Passenger A. Vale / Seat 0A | 뒷면 롤러 자국, 구형 항공사 코드, 금속가루 |
| 수하물 태그 | Adrian 이름과 편명 | 찢김 방향, 카운터 스테이플 흔적 |
| 익명 편지 | 전방 화장실 패널 지시 | 봉투 접착부 NX-17 윤활제 |
| 개조 나사 | 다른 색과 머리 모양 | 전용 공구의 비대칭 긁힘 |
| Ruby 카메라 | 최근 영상 목록 | 휴지통, 메타데이터, 렌즈 설탕가루 |
| Silver Briefcase | 잠금과 표면 흠집 | 이중 바닥, Flight 308 원본 기록 |

### 5.4 사건 수첩

| 탭 | 콘텐츠 | 플레이 기능 |
|---|---|---|
| Evidence | 증거 카드, 조사 완료도, 관련 인물 | 심문 제시, Final Deduction 재료 |
| People | 프로필, 현재 좌석, 진술 요약 | 주제와 모순 후보 확인 |
| Timeline | 운항 시간, 방송, 조명, 카트 위치 | PZ-07 제약 근거 |
| Map | 공항 장소, 기내 좌석표 | 빠른 이동, 조사 가능 지점 |
| Questions | 현재 해결할 질문 2-4개 | 서사적 목표 표시 |

- 최근 획득 항목으로 자동 포커스하되 사용자가 다른 항목을 고정할 수 있다.
- 열기 목표는 0.3초 이내다.
- Final Deduction과 최종 심문 중에도 열 수 있다.

### 5.5 힌트와 난이도

| 기능 | 스토리 | 표준 | 분석가 |
|---|---|---|---|
| 핫스폿 | 항상 은은한 표시 | 20초 후 표시 | 표시 없음 |
| 일반 퍼즐 힌트 | 60/120/180초 | 90/180/300초 | 수동 요청만 |
| Timeline 오류 | 원인 제약 직접 표시 | 제약 종류만 표시 | 충돌 수만 표시 |
| 결말/콘텐츠 | 동일 | 동일 | 동일 |

- 퍼즐별 명시된 힌트는 공통 타이머를 덮어쓸 수 있다.
- 90초 관찰, 180초 Noah 방향, 300초 직접 조작이라는 표준 단계는 유지한다.
- 직접 조작 힌트도 자동 해결은 하지 않는다.
- PZ-07 스토리 모드에서는 불가능한 좌석을 회색 처리한다.

### 5.6 저장과 재개

- 자동 저장: 장소 진입, 증거 획득, 퍼즐 완료, 심문 단계 종료.
- 수동 슬롯 5개, 자동 슬롯 3개.
- PZ-07 진입 직전 별도 체크포인트.
- 챕터 선택은 1회 클리어 후 해금.
- 챕터 선택 시 증거와 플래그를 해당 챕터 시작 기준 스냅샷으로 복원.
- 챕터 경계 저장을 불러와도 컷신과 음성이 중복 재생되지 않는다.
- 각 세이브는 `schema_version`, 챕터, 장면, GameState, 플레이 시간, 난이도, 저장 시각을 가진다.
- 파일은 임시 파일에 쓴 뒤 교체하고 이전 정상본을 한 세대 보존한다.

### 5.7 성능과 플랫폼

- 기준 해상도 1920x1080, 16:9.
- 1280x720 이상에서 UI 구조를 재배치하지 않고 동작.
- PC 최소 사양 60fps 목표.
- 장면 전환 2초 이내, 사건 수첩 0.3초 이내.
- 마우스/키보드와 XInput 패드 동시 지원.
- 터치 포팅을 위한 최소 터치 영역 9mm.
- 완전 오프라인 싱글 플레이. 클라우드 저장은 플랫폼 기능에 위임한다.
- 프로파일링은 메모리, 배경 텍스처 로드, 음성 스트리밍, 장면 전환에 집중한다.

## 6. GDD 전체 범위 구현 레지스터

이 절은 “요약본”이 아니라 출시 범위 원장이다. 각 항목은 삭제하지 않고 백로그, 데이터, 테스트 중 하나와 연결한다.

### 6.1 제품 비전과 경험 원칙 - GDD p.5-6

중심 질문:

- 표면 질문: “Who entered the locked room?”
- 실제 질문: “아무도 들어갈 필요가 없었다면?”
- 플레이어는 화장실 문을 연 사람보다 밀실이 만들어지기 전 행동을 역추적한다.
- 공항에서 무심코 본 장면이 기내 살인의 준비 과정으로 재해석될 때 가장 큰 추리 쾌감을 제공한다.

세 가지 약속:

1. 공항도 범죄 현장이다.
   - 탑승 전 40분의 관찰을 이후 모든 심문과 퍼즐의 재료로 사용한다.
   - 공항 정보를 기내에서 반드시 재사용한다.
2. 좌석표가 추리 보드다.
   - 대사뿐 아니라 좌석, 카트, 조명, 안전벨트 로그로 이동 가능성과 물리 차단을 직접 검증한다.
3. 틀려도 계속 생각한다.
   - 오답은 짧은 반응만 만들고 재검증을 장려한다.
   - 힌트는 단계적으로 제공한다.

차별점:

| 일반적인 방식 | SEAT 0A 구현 |
|---|---|
| 사건 후 현장에 도착 | 사건 전 공항이 준비 과정이자 단서 저장소 |
| 대화의 거짓말만 지적 | 좌석·카트·조명·안전벨트로 이동 가능성까지 검증 |
| 밀실에 들어간 범인을 찾음 | 장치 설치 시점을 밝혀 질문 자체를 뒤집음 |
| 진행을 잠그는 미니게임 | 모든 퍼즐이 새 증거 또는 증언을 출력 |
| 용의자마다 독립 사연 | Flight 308이 모든 동기와 오해를 연결 |

타깃:

- 대사와 관찰 중심 미스터리를 좋아하고 고난도 액션·시간 압박은 선호하지 않는 플레이어.
- 2-3시간 안에 완결된 사건을 원하는 스트리밍 친화적 인디게임 이용자.
- 증거 제시, 심문, 사건 재구성과 같은 명확한 추리 피드백을 선호하는 플레이어.
- 캐릭터 코미디는 좋아하지만 사건 논리와 감정의 무게가 가벼워지는 것은 원하지 않는 플레이어.

감정 곡선:

| 구간 | 감정 | 구현해야 할 연출 |
|---|---|---|
| 공항 탐색 | 호기심, 가벼운 코미디 | 인물을 기억시키고 작은 이상 징후 축적 |
| 이륙/봉투 | 불안, 예감 | 평범한 여행에서 사건으로 전환됨을 명확히 표시 |
| 시신 발견 | 충격, 폐쇄감 | 기내 소음 감쇠, 시야 축소 |
| 심문/반증 | 의심, 지적 쾌감 | 실제 동기를 보여주되 조기 정답 방지 |
| Cabin Timeline | 혼란에서 확신 | 모두의 접근 불가능이라는 역설 시각화 |
| 최종 심문 | 긴장, 해소 | 방법 -> 동기 -> 0A 순으로 잠금 해제 |
| 에필로그 | 여운, 정의의 불완전함 | 살인 해결과 Flight 308 재조사를 구분 |

### 6.2 핵심 루프와 플레이어 동사 - GDD p.7-8

핵심 루프:

`현장 관찰 -> 증거 확보 -> 증언 기록 -> 모순 제시 -> 동선 재구성`

루프 완료는 단순 획득이 아니라 기존 증언의 의미가 바뀌거나 다음 장소/심문이 열릴 때다. 선택 핫스폿도 관찰 기록, 인물 이해, 추가 대사 중 하나를 남겨 정보 상태를 바꾼다.

| 동사 | 입력 | 결과 |
|---|---|---|
| 이동 | 화면 가장자리/장소 목록 | 고정 배경 전환, 인물·핫스폿 갱신 |
| 관찰 | 핫스폿 선택 | Claire 관찰문, 증거 또는 대화 주제 |
| 확대 조사 | 증거 카드의 조사 | 회전, 앞/뒤, 확대, 조사 부위 포커스 |
| 대화 | 인물 뒤 주제 카드 | 증언, 호감/긴장, 모순 후보 |

### 6.10 Final Deduction과 최종 심문 - GDD p.26, p.34

정답:

- WHO: Marcus Reed. 사전 탑승, 가방 접근, 전용 공구, 동일 윤활제, 과거 기록 조작이 한 인물로 수렴.
- HOW: 사전 설치된 패널 장치. Adrian이 편지대로 패널을 열 때 기계식 충격 장치가 작동. 문은 실제 안쪽 잠금.
- WHY: Flight 308 기록 은폐. 원본 공개 시 Marcus의 로그 조작과 불법 부품 가담으로 형사 책임.
- WHAT IS 0A: Flight 308 불법 정비 프로젝트 `Operation 0A`. 가짜 탑승권은 유인과 오도.

네 질문의 순차 해금:

| 순서 | 질문 | 정답 | 원문 후보 증거 |
|---|---|---|---|
| 1 | Adrian은 언제 공격받았나? | 화장실에 들어간 뒤가 아니라 패널을 여는 순간 | E05, E07, E11/E12 |
| 2 | 장치는 언제 설치됐나? | Flight 709 출발 전 | E14, E03, E15 |
| 3 | 누가 설치했나? | Marcus Reed | E10, E08, E15 |
| 4 | Seat 0A는 무엇인가? | Operation 0A | E06, E09, E16 |

화면은 증거 슬롯 2개만 가진다. 원문의 후보를 지우지 않고 독립 그룹 방식으로 판정한다.

- 질문 해금에는 표의 모든 후보 증거 획득이 필요하다. Q1의 `E11/E12`만 OR 조건이다.
- Q1: 장치/유인 그룹 `{E05,E07}`에서 하나 + 시간/이동 그룹 `{E11,E12}`에서 하나.
- Q2: 사전 접근 그룹 `{E14,E03}`에서 하나 + 전용 도구 `E15`.
- Q3: 직접 영상 `E10` + 물리 연결 `{E08,E15}`에서 하나.
- Q4: 프로젝트 원본 `E16` + 제작/취재 연결 `{E09,E06}`에서 하나.

즉 모든 후보는 해금에 쓰이고, 선택한 두 장은 화면에서 대표 논증을 구성한다. 이 유효 쌍은 프리프로덕션 공정성 리뷰에서 승인한다.

최종 심문 순서:

| 단계 | Marcus 방어 | 반박 | 연출 |
|---|---|---|---|
| 1 접근 부정 | “사건 때 나는 14C에 있었다.” | 맞기 때문에 장치는 사건 전에 설치 | 첫 침묵 |
| 2 사전 탑승 축소 | “갤리 점검만 했다.” | 사전 탑승+전방 영상+개조 나사 | 카메라가 공구 가방으로 이동 |
| 3 가방 접촉 부정 | “Adrian 가방은 모른다.” | 삭제 영상+봉투 윤활제 | 답변 속도가 느려짐 |
| 4 동기 부정 | “Flight 308과 관계없다.” | 원본 로그 서명+Operation 0A | 객실 소음 감쇠, 과거 회상 |
| 5 결론 | 조직 명령과 공포 주장 | 현재 살인은 개인 선택 | 기장 방송, 착륙등 |

오답:

- 잘못된 범인은 동기/수단/사전 설치 기회 중 빠진 범주를 Claire가 지적한다.

- 잘못된 0A는 탑승권 뒷면과 Flight 308 메모를 나란히 보여준다.
- 최종 심문 중에도 수첩을 열 수 있다.
