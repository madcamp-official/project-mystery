# Under the Horizon 맵 시스템 개편 구현 기록

## 목적

층별 설계도를 단순 빠른 이동 목록이 아니라 플레이어가 현재까지 확인한 선박
구조, 목표 장소, 알려진 인물의 마지막 목격 위치와 접근 제한을 함께 확인하는
수사 화면으로 사용한다.

원본 레이어 파일과 매니페스트는 `Documentation/Source/MapLayers`에 보관하고,
런타임용 층별 이미지와 항구 Base는
`Assets/_Project/Resources/Maps/DeckLayers`에서 관리한다.

## 물리 장소 계약

동일한 배경을 사용하더라도 이야기상 다른 공간은 별도 장소 코드로 유지한다.

| 이야기 장소 | 물리 장소 | Deck |
| --- | --- | ---: |
| `SERVICE7` | `SERVICE7` | 7 |
| `CABIN_DANIEL` | `CABIN_DANIEL` | 7 |
| `BRIDGE` | `BRIDGE` | 10 |
| `CABIN_CLAIRE` | `CABIN_CLAIRE` | 8 |
| `INTERVIEW` | `INTERVIEW` | 10 |

기존에 위 장소들을 각각 `CREW_STAIRS`, `NEWS_LOUNGE`,
`ENGINE_CONTROL`, `VIP_LOUNGE`, `SECURITY`에 합치던 별칭은 제거했다.
장소 카탈로그와 그래프는 항구를 포함한 30개 물리 장소를 가진다. 이 중
Deck 10·9·8·7과 항구의 24개만 플레이 가능하며, Deck 6의 6개 장소는
비사용 메타데이터로만 보존한다.

## 지도 레이어

- 선내도: 처음부터 사용 가능
- 수사 주석: `D1-04` 완료 후 사용 가능
- 설비도: 기관 제어실과 화물 레일 조사를 모두 마친 `D6-02` 완료 후 사용 가능

표시 순서는 Base, 동적 제한영역, 수사 주석 폴백, Technical, 장소 노드다.
Deck 7~10은 `MapAreaCatalog`의 0~1 정규화 폴리곤을 사용하므로 제한구역마다
틴트, 외곽선, 해칭과 출입구 잠금 표시를 독립적으로 갱신한다. 접근 가능 상태가
되면 해당 구역의 틴트와 잠금만 제거되고, 승객용 복도와 장소 노드는 항상
그 위에서 정상적으로 보인다. 승객 불안이 제한 임계치에 도달하면 구역은
붉은 임시 폐쇄 상태로 바뀐다.

기존 `DeckXX_Restricted.png` 이름은 Unity GUID 호환을 위해 유지한다. 동적
카탈로그가 없는 덱에서만 런타임 폴백으로 표시하며, 활성 덱에서는 에디터 합성
미리보기와 시각 QA 기준으로 사용한다. 따라서 `Investigation`은 더 이상 층
전체를 가리는 상태가 아니라 플레이어가 확인한 구역과 조사 정보를 더하는
레이어다.

설비도 해금을 단순히 Day 6 씬이 열리는 시점으로 판단하지 않는다. 화물 레일은
핵심 트릭이므로 `D6-02` 완료 전에는 기술 오버레이를 표시하지 않는다.

## 이동 규칙

| 등급 | 동작 |
| --- | --- |
| 공개 빠른 이동 | 승선 완료 후 지도에서 이동 가능 |
| 조건부 빠른 이동 | 해당 장소의 장면을 알게 된 뒤 이동 가능 |
| 현장 경유 전용 | 지도에서 직접 재방문할 수 없고 지정 장면이나 인접 경로로 진입 |

장소 노드를 한 번 선택하면 우측 상세 패널에 한국어 장소명, 층, 설명, 알려진
인물과 잠금 이유가 표시된다. 실제 이동은 별도의 `이동하기` 확인 버튼으로만
실행한다. 이동 때는 입력을 막는 짧은 화면 페이드 아웃/인이 적용된다.

진행 중인 공식 장면 이동은 현장 경유 전용 제한보다 우선한다. 따라서
`ENGINE_CONTROL`, `SERVICE_RAIL`, `BALLAST_CONTROL_ANNEX` 같은 장소가 자유
빠른 이동 대상이 아니어도 해당 목표 장면은 정상적으로 시작할 수 있다.

## UI와 입력

- `M`: 현재 화면과 지도 사이를 전환
- `Esc`: 지도를 닫고 지도를 열기 전 화면으로 복귀
- 층 탭: Deck 10, 9, 8, 7, 항구
- 레이어 탭: 선내도, 수사 주석, 설비도
- 장소 노드: 현재 위치, 주요 목표, 접근 불가를 텍스트와 기호로 함께 구분
- 상세 패널: 내부 씬 ID나 플래그 대신 자연어 상태만 표시

지도에서 증거 화면으로 잘못 복귀하던 문제를 막기 위해, 지도 진입 전의 기본
패널을 기록하고 닫을 때 복원한다.

## 스토리·대사·목표 검수 계약

자동 검수는 다음을 확인한다.

1. 공식 41개 장면과 41개 메인 목표가 일대일로 대응한다.
2. 각 목표의 대상 장소가 해당 장면의 대사 장소 코드와 같다.
3. 모든 장면 장소가 물리 장소와 지도 배치로 해석된다.
4. 지도 배치의 Deck이 물리 장소 카탈로그의 Deck과 같다.
5. 장면 인물 배치의 중심 장소가 대사·목표의 장소와 같다.
6. 24개 플레이 가능 장소가 중복 없이 활성 지도 배치 하나씩을 가진다.
7. Deck 6의 6개 비사용 장소가 별도 비사용 배치로만 유지되고 런타임 층
   선택과 이동에서 제외된다.
8. 경유 전용 지도 제한이 공식 스토리 장면 진입을 막지 않는다.
9. 수사·설비 레이어가 정해진 완료 시점보다 먼저 열리지 않는다.
10. 모든 활성 제한 폴리곤과 출입구가 0~1 좌표 안에 있고 자기 교차하지 않는다.
11. 활성 `RouteOnly` 장소마다 같은 Deck의 제한영역 데이터가 존재한다.
12. Base·Restricted·Technical 레이어가 1448×1086 및 동일한 Sprite 설정을
    유지한다.

귀빈 라운지는 공식 장면·목표·증거를 직접 시작하지 않는 주변 대사 중심의 공용 장소이므로,
승선 완료 뒤 자유 이동 예외로 개방한다. 그 외 미래 장면 목적지는 장면 해금과 선행 조건을
따르며, 공식 장면이 없는 기술 구역은 경유 전용 상태를 유지한다.

관련 회귀 테스트는
`Assets/_Project/Tests/EditMode/MapStoryIntegrationTests.cs`,
`ScenePresenceCatalogTests.cs`, `SceneTravelPolicyTests.cs`에 있다.

## 호환성과 자산

새로 분리한 다섯 장소는 독립 장소 자산을 사용한다. 전용 배경 일러스트가 아직
없으므로 기존 공유 배경을 임시로 재사용하지만, 장소 코드·층·이동 상태와
스토리 진행 상태는 더 이상 공유하지 않는다.

지도 PNG는 Unity에서 단일 Sprite, 밉맵 비활성화, 알파 투명도 사용, Clamp
래핑으로 가져온다. 임포트 규칙은
`Assets/_Project/Editor/MapLayerAssetImporter.cs`에 있다.

`Wake > Map Area Authoring` 창에서는 Base 이미지를 선택하고 벽 안쪽
꼭짓점, 이름 위치와 출입구를 마우스로 지정할 수 있다. Passenger,
Investigation, Technical 합성 미리보기와 0~1 범위·자기 교차 검증을 거쳐
`Resources/Maps/MapAreaCatalog.asset`에 저장한다. 해당 에셋이 없으면 코드에
포함된 검증 완료 기본 카탈로그를 사용한다.

항구 탭의 기본 레이어는
`Assets/_Project/Resources/Maps/DeckLayers/Port_Base.png`를 사용한다.
항구와 승선 통로 노드는 다른 층과 동일하게 이미지 위 UI 노드로 표시하며,
항구에는 조사·설비 오버레이를 별도로 두지 않는다.
