# Under the Horizon Codex Goal 프롬프트

## 사용법

아래 프롬프트를 Codex Goal의 objective로 사용한다.

프로젝트 경로, 저장소 권한, 공식 파일 개정일이 바뀌면 먼저 해당 값을 수정한다.

완료 조건 일부만 충족한 상태에서 Goal을 완료 처리하지 않는다.

사용자에게 보이는 UI 표현과 상호작용은
`Documentation/Under_the_Horizon_UI_Decision_Record_KR.md`를 우선 적용한다.

```text
Under the Horizon Unity 프로젝트를 최신 공식 문서와 대사집에 맞춰
처음부터 끝까지 정상적으로 플레이 가능한 상태로 완성한다.

UI 기준:
- UI Basic Scene을 제품 플레이 진입점으로 사용한다.
- 기본 사용자 화면 38종과 상태 변형 2종을 WF-01부터 WF-40으로 관리한다.
- 41개 장면마다 UI를 복제하지 않고 공통 화면 셸과 7구역 슬롯을 조합한다.
- 화면 정의는 Documentation/Under_the_Horizon_UI_Wireframe_Spec_KR.md를 따른다.
- 제작 순서는 Documentation/Under_the_Horizon_UI_Wireframe_Production_Order_KR.md를 따른다.
- 기준 화면비는 16:9다.
- 기준 해상도는 1920x1080이다.
- 16:10의 1920x1200도 지원한다.
- 1280x720과 UI 100~160% 확대를 검증한다.
- 다른 화면비에서도 주요 조작을 잃지 않게 한다.
- Safe Area와 stretch anchor를 사용한다.
- 고정 좌표만으로 전체 화면을 구성하지 않는다.
- Ingame 루트는 전체 캔버스 stretch와 scale 1을 유지한다.

공통 7구역:
- 좌상단은 현재 문맥, 뒤로가기와 취소다.
- 상단은 화면 제목, 현재 목표와 퍼즐 질문이다.
- 우상단은 조사 기록, 지도, 도움말, 일시정지와 닫기다.
- 좌하단은 보조 도구, 필터, 질문 주제와 이전 행동이다.
- 하단은 대사, 설명, 자연어 피드백과 시간축이다.
- 우하단은 현재 화면의 가장 중요한 행동 하나다.
- 중앙은 배경, 캐릭터, 지도, 기록과 퍼즐 조작 영역이다.

진입·시스템 화면:
- 타이틀 메뉴는 시작, 설정, 크레딧, 종료만 제공한다.
- 새 게임과 이어하기를 타이틀에서 분리하지 않는다.
- 시작을 누르면 저장 슬롯 3개를 표시한다.
- 저장이 있는 슬롯은 이어서 시작하고 빈 슬롯은 프롤로그를 시작한다.
- 부팅, 타이틀, 저장 슬롯, 로딩, 설정, 크레딧과 확인 모달에 플레이 HUD를 표시하지 않는다.

배경 표시:
- 16:9 원본 배경을 16:10에 맞춰 늘이지 않는다.
- 원본 종횡비를 유지한다.
- cover 방식으로 화면을 채운다.
- 화면 밖으로 나가는 부분은 중앙 기준으로 자른다.
- 장소별 초점과 위치 보정값을 지원한다.
- 중요한 단서와 핫스폿은 안전 영역에 둔다.
- 16:9와 16:10에서 배경이 찌그러지지 않아야 한다.

탐색 UI:
- 장소 배경 안에 전신 인물 1~4명을 배치한다.
- 인물, 소품과 출입구 자체를 직접 클릭한다.
- 하단의 인물 대화 버튼을 중복 제공하지 않는다.
- 클릭 포인트, 이름표와 윤곽은 기본 상태에서 숨긴다.
- 호버, 키보드·게임패드 포커스와 접근성 탐색 모드에서만 대상 정보를 표시한다.
- 이동 지점 1~3개, 환경 대상 4~8개, 확대 조사 진입점 1~3개를 권장한다.

대사 UI:
- 대사 패널을 하단 안전 영역 안에 둔다.
- 긴 대사가 화면 밖으로 나오지 않아야 한다.
- 긴 대사를 삭제하거나 말줄임하지 않고 페이지 또는 스크롤로 모두 표시한다.
- 화자명은 한 줄 말줄임을 사용한다.
- 다음 버튼을 대사 패널 내부에 둔다.
- 다음 버튼이 어떤 화면비에서도 클릭 가능해야 한다.
- 선택지가 많아지면 동적 레이아웃과 스크롤을 사용한다.
- 선택지 버튼이 서로 겹치지 않아야 한다.
- 선택지 전체를 키보드와 마우스로 확인할 수 있어야 한다.
- 대화 선택 상태에서는 다음 대사와 선택 확정 입력이 중복되지 않아야 한다.

인물 초상:
- 하드코딩된 절대 좌표를 제거한다.
- 좌측, 우측, 중앙 표시 규칙을 데이터로 구분한다.
- 원본 종횡비를 유지한다.
- 초상이 대사와 선택지를 가리지 않게 한다.
- 초상이 현재 목표와 우상단 전역 기능을 가리지 않게 한다.
- 화자 변경 시 잘못된 이전 초상이 남지 않아야 한다.
- 초상이 없는 화자도 대사를 진행할 수 있어야 한다.

상단 UI:
- 지도, 조사 기록, 일시정지를 우상단 안전 영역에 둔다.
- 숫자형 Trust, 불안도, 현장 보존도 HUD를 표시하지 않는다.
- 내부 상태 수치는 유지하고 필요한 순간에만 자연어 메시지를 표시한다.
- 단서 코드, 총 단서 수와 수집률을 사용자 UI에 표시하지 않는다.
- 패널이 안전 영역 밖으로 나가지 않아야 한다.
- 패널을 닫은 뒤 대사 입력을 복구한다.
- 패널 중첩으로 클릭이 차단되지 않게 한다.
- 배경과 텍스트 대비를 확보한다.

오버레이와 모달:
- 원래 화면이 보이도록 배경을 약 55~65% 어둡게 한다.
- 취소 입력은 가장 위에 열린 패널 하나만 닫는다.
- 확인은 우하단, 취소는 좌상단 또는 좌하단에 둔다.
- 패널을 닫으면 직전 포커스와 입력 소유권을 복구한다.
- 지도와 조사 기록을 닫으면 진입 전 화면과 카메라 상태를 복구한다.
- 새 기록, 상태 변화와 목표 갱신 알림을 겹치지 않게 순차 표시한다.

증거와 퍼즐:
- C-01부터 C-18까지 수집 상태를 저장한다.
- Evidence_Master의 표시명과 역할을 사용한다.
- 필수 증거를 영구히 놓치는 분기를 만들지 않는다.
- 출구 조사 퍼즐을 공식 현장 흐름과 연결한다.
- Marcus 심문 퍼즐을 공식 대사와 연결한다.
- Orpheus 음성 복원 퍼즐을 공식 대사와 연결한다.
- 타임라인 퍼즐에서 21:45와 22:18을 구분한다.
- 성공, 실패, 힌트 피드백을 제공한다.
- 색상만으로 상태를 구분하지 않는다.
- 13개 퍼즐은 공통 Puzzle Shell을 사용하고 중앙 조작부를 퍼즐별로 교체한다.

브랜치 규칙:

- 종속 변경은 직전 작업 브랜치에서 분기한다.
- 후속 PR은 직전 PR 브랜치를 base로 사용한다.
- 이전 PR 병합을 기다리지 않는다.
- 이전 PR 자동 병합을 기다리지 않는다.
- 충돌을 숨기기 위해 history를 강제로 바꾸지 않는다.

PR 크기:
- 의미 있는 코드 및 텍스트 변경량을 300~500줄로 나눈다.
- PNG, PDF, XLSX 등 바이너리는 줄 수 계산에서 제외한다.
- 생성 데이터는 줄 수 목표를 채우는 용도로 쓰지 않는다.
- 의미 없는 주석으로 줄 수를 채우지 않는다.
- 500줄이 넘으면 기능 경계로 나눈다.
- 300줄보다 작아도 억지 분리가 품질을 해치면 응집도를 우선한다.
- 예외 이유를 PR 본문에 설명한다.

커밋과 PR 제목:
- feat:, fix:, docs:, test:, refactor:, chore: 중 하나를 쓴다.
- 괄호 scope를 사용하지 않는다.
- 접두사 뒤에는 명확한 한국어 결과를 쓴다.
- 예: fix: 프로덕션 씬 진행 상황 유지
- 예: fix: 16대9 화면에서 버튼 이탈 방지
- 예: feat: 최신 대사집 자동 가져오기 추가
- 예: docs: 공식 자료와 구현 기준 통합
- 구현 클래스명만 나열하는 모호한 제목을 피한다.
```
