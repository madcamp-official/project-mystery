# Under the Horizon 화면별 와이어프레임 제작 순서

## 1. 문서 정보

| 항목 | 값 |
|---|---|
| 상태 | 실행 순서 확정 |
| 작성일 | 2026-07-28 |
| 대상 | WF-01~WF-40 |
| 기준 문서 | `Under_the_Horizon_UI_Wireframe_Spec_KR.md` |
| 결정 문서 | `Under_the_Horizon_UI_Decision_Record_KR.md` |
| 제작 묶음 | 4차 |

이 문서는 40개 와이어프레임 상태를 어떤 순서로 제작하고 검수할지 정의한다.

화면의 구역, 크기, 입력과 표시 규칙은 와이어프레임 기준서를 따르며 이 문서에서
다시 정의하지 않는다.

이번 문서는 제작 순서와 단계별 완료 조건만 다룬다.

## 3. 준비 게이트

1차 제작을 시작하기 전에 다음 산출물을 한 번만 만든다.

- 1920×1080 기준 프레임
- 1920×1200 비교 프레임
- 1280×720 축소 프레임
- 7구역 Safe Area 가이드
- 기본 레이어와 Z 순서 가이드
- 키보드·게임패드 포커스 번호 표기
- 우하단 주요 행동 표식
- 오버레이용 55~65% 배경 딤 샘플
- 빈 상태, 잠김 상태, 오류 상태 주석 양식
- UI 100%, 130%, 160% 확대 비교 양식

### 준비 완료 조건

- 모든 화면이 같은 7구역 마스터를 복제해 시작할 수 있다.
- 화면 ID, 화면명, 셸, 최초 포커스와 주요 행동을 적는 공간이 있다.
- 기준 화면비를 바꿔도 Safe Area가 유지된다.
- 숫자형 상태 HUD가 마스터에 포함되어 있지 않다.

### 4.2 제작 패스

#### 패스 A: 진입 골격

- WF-01 → WF-02 → WF-03 → WF-04의 연속 흐름을 먼저 배치한다.
- 타이틀에서 `새 게임`과 `이어하기`를 분리하지 않는다.
- WF-03에서 빈 슬롯과 기존 저장 슬롯의 정보 차이를 표시한다.

#### 패스 B: 플레이 중 시스템

- WF-06과 WF-07을 같은 패널 계층으로 설계한다.
- 설정을 닫으면 일시정지 화면의 이전 항목에 포커스가 돌아오는 것을 주석으로 남긴다.
- WF-09 확인 모달은 저장 삭제, 덮어쓰기, 타이틀 이동, 종료에 재사용한다.

#### 패스 C: 전환과 안내

- WF-04, WF-05, WF-08의 건너뛰기·계속 입력을 통일한다.
- WF-01과 WF-04에서는 완료 전 입력 차단 영역을 명시한다.
- WF-10에서 라이선스와 사용 리소스 표기 영역을 확보한다.

### 4.3 1차 완료 조건

- WF-01~WF-10이 모두 존재한다.
- 타이틀과 저장 슬롯에서 플레이용 HUD가 보이지 않는다.
- 시작 후 저장 슬롯 3개로 이동하는 흐름이 명확하다.
- 확인은 우하단, 취소와 뒤로가기는 좌측에 있다.
- 설정과 확인 모달을 닫았을 때 복귀 포커스가 표시되어 있다.
- 16:9, 16:10, 1280×720 비교본이 있다.

### 5.2 탐색 패스

- WF-11을 2차의 기준 화면으로 먼저 승인한다.
- 전신 인물 1명, 2명, 4명 배치 변형을 각각 검토한다.
- 이동 지점 1~3개, 환경 대상 4~8개, 조사 진입점 1~3개를 주석으로 표시한다.
- 기본 상태에서는 이름표와 클릭 아이콘을 숨긴다.
- 호버, 키보드·게임패드 포커스, 접근성 탐색 상태를 별도 레이어로 작성한다.
- 지도·조사 기록·일시정지가 우상단에서 같은 순서를 유지하는지 확인한다.

### 5.3 대화 패스

- WF-13을 승인한 뒤 같은 프레임을 복제해 WF-14와 WF-15를 만든다.
- 화자 단독, 두 인물 대화, 초상 없는 화자의 변형을 검토한다.
- 짧은 대사, 긴 대사 2페이지, 가장 긴 대사의 상태를 작성한다.
- WF-14는 선택지 2개, 3개, 5개와 UI 160% 상태를 검토한다.
- 선택지가 열렸을 때 다음 대사 버튼과 확정 버튼이 중복되지 않게 한다.

### 5.4 조사·기록 패스

- WF-16에서 조사 도구의 위치와 중앙 확대 영역을 먼저 확정한다.
- WF-17 → WF-18 → WF-19 순서로 기록 탐색, 활용, 획득 피드백을 연결한다.
- 단서 코드, 총 단서 수, 수집률을 와이어프레임에 넣지 않는다.
- 기록은 자연어 이름, 분류, 발견 장소와 관련 인물로 식별한다.

### 5.5 심문·컷신 패스

- WF-20의 일반 심문을 기준으로 WF-21의 제한 규칙을 추가한다.
- 관계와 태도는 숫자 대신 자연어로 표시한다.
- WF-21은 남은 질문 기회만 현재 규칙상 필요한 진행 정보로 표시한다.
- WF-22는 컷신 중 허용되는 입력과 자막 Safe Area를 표시한다.

### 5.6 2차 완료 조건

- WF-11~WF-22가 모두 존재한다.
- 인물과 소품 자체를 직접 선택하는 구조가 보인다.
- 클릭 포인트는 호버·포커스·접근성 상태에서만 표시된다.
- 긴 대사가 생략되지 않고 페이지로 나뉜다.
- 지도와 조사 기록을 닫을 때 복귀 화면과 포커스가 주석으로 표시된다.
- 심문 화면에 내부 Trust 숫자가 노출되지 않는다.
- 모든 화면에서 우하단 주요 행동이 하나로 식별된다.

1. 좌상단 단계·도구 분류
2. 상단의 해결 질문
3. 우상단 힌트·초기화·나가기

### 6.3 그룹 내부 제작 패스

각 퍼즐은 다음 순서로 작성한다.

1. 목표 질문만 보이는 초기 상태
2. 일부 조작이 완료된 진행 상태
3. 잘못된 조작 피드백
4. 힌트 1단계 표시

6. 성공 결과
7. 중간 이탈 확인 모달

퍼즐별로 완전히 다른 상단·하단 UI를 만들지 않고 중앙 조작부와 필요한 보조
도구만 변경한다.

### 6.4 최종 지목

13개 퍼즐을 승인한 뒤 WF-36을 제작한다.

제작 순서는 다음과 같다.

1. 1/6 범인
2. 2/6 실제 살해 장소
3. 3/6 직접 사인
4. 4/6 시신 운반법
5. 5/6 유인 동기
6. 6/6 오르페우스호 설계자
7. 전체 논증 검토
8. 최종 확정 모달

각 단계에서 후보 카드, 필수 기록 슬롯, 지금까지 구성한 자연어 논증 문장을
같은 위치에 유지한다.

### 6.5 3차 완료 조건

- WF-23~WF-36이 모두 존재한다.
- 13개 퍼즐이 같은 `Puzzle Shell`을 사용한다.
- 모든 퍼즐에 초기, 진행, 오류, 힌트, 성공과 중간 이탈 상태가 있다.
- 중앙 조작부를 제외한 공통 기능의 위치와 의미가 동일하다.
- 색상 이외의 형태와 문구로 정답·오답·잠김을 구분한다.
- WF-36이 정확히 6개 논증 단계를 제공한다.
- 최종 확정 전에 전체 논증을 검토할 수 있다.

## 7. 4차: 엔딩과 재플레이

| 2 | WF-38 | 인물 후일담 | 인물 탭, 본문, 다음 인물 | 인물별 결과 탐색 |

### 7.2 엔딩 변형

WF-37은 공통 골격 한 장과 다음 콘텐츠 변형을 검토한다.

- A 엔딩
- B 엔딩
- C 엔딩
- Bad 엔딩

엔딩마다 버튼 위치를 바꾸지 않고 결과 문구와 중앙 일러스트만 변경한다.

WF-38은 주요 인물 탭 수가 늘어날 때의 가로 스크롤 또는 목록 전환을 검토한다.

WF-39는 잠긴 챕터, 해금 챕터, 현재 선택 챕터의 차이를 색상 이외의 표식으로
구분한다.

WF-40은 마지막 체크포인트가 있는 상태와 복구할 체크포인트가 없는 상태를
각각 작성한다.

### 7.3 4차 완료 조건

- WF-37~WF-40이 모두 존재한다.
- A, B, C, Bad 결과가 같은 엔딩 셸에서 표현된다.
- 후일담에서 인물을 바꿔도 읽기 위치와 주요 행동이 유지된다.
- 재플레이의 잠김·해금 상태를 색상 없이 구분한다.
- 배드 엔드에서 체크포인트와 타이틀 이동의 결과가 명확하다.

## 8. 각 화면의 공통 제작 절차

모든 WF 상태는 다음 다섯 패스를 순서대로 거친다.

- 중앙 핵심 콘텐츠

## 9. 검수 게이트

### 게이트 A: 1차 승인

게임 시작, 저장 슬롯, 일시정지와 설정 흐름이 확정되어야 2차를 시작한다.

### 게이트 B: 2차 승인

탐색, 대화, 조사와 심문의 공통 셸이 확정되어야 퍼즐 화면을 제작한다.

### 게이트 C: Puzzle Shell 승인

공통 퍼즐 셸을 승인한 뒤에만 13개 중앙 조작부를 병렬 제작한다.

### 게이트 D: 최종 지목 승인

13개 퍼즐의 공통 피드백과 기록 제시 규칙이 확정된 뒤 WF-36을 승인한다.

### 게이트 E: 전체 일관성 승인

엔딩과 재플레이까지 완료한 뒤 WF-01~WF-40의 위치, 용어와 입력 규칙을 한 번에
비교한다.

## 11. 제작 순서 완료 조건
