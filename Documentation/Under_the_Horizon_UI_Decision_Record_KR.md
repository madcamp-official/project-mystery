# Under the Horizon UI 결정 기록

## 문서 정보

| 항목 | 값 |
|---|---|
| 상태 | 승인 |
| 결정일 | 2026-07-28 |
| 적용 범위 | 사용자에게 보이는 UI 정보 구조, 화면 배치, 상호작용 표현 |
| 제외 범위 | 사건 진상, 대사 원문, 내부 게임 상태 계산, 저장 데이터 식별자 |

이 문서는 기존 프로덕션 매뉴얼과 프로젝트 문서에 흩어진 UI 표현 규칙을
현재 제작 방향에 맞게 정리한 결정 기록이다.

이 문서와 기존 UI 설명이 충돌하면 사용자에게 보이는 UI 표현에는 이 문서를
우선 적용한다. 사건, 장면, 대사, 장소, 엔딩과 내부 상태 계산은 기존 공식 원본의
우선순위를 그대로 따른다.

## 결정 사항

### UI-DEC-001 공식 표기

- 사용자에게 보이는 정식 제목은 `Under the Horizon`만 사용한다.
- 이전 작업명은 저장 데이터 마이그레이션 등 내부 호환 목적에만 남긴다.

### UI-DEC-002 타이틀 메뉴

- 타이틀 메뉴는 `시작 / 설정 / 크레딧 / 종료` 네 항목만 사용한다.
- 타이틀에서 `새 게임`과 `이어하기`를 별도 항목으로 나누지 않는다.

### UI-DEC-003 저장 슬롯 진입

- 플레이어가 `시작`을 선택하면 저장 슬롯 선택 화면으로 이동한다.
- 저장 슬롯은 세 개를 제공한다.
- 저장 데이터가 있는 슬롯을 선택하면 해당 저장을 이어서 시작한다.
- 빈 슬롯을 선택하면 프롤로그부터 시작한다.

### UI-DEC-004 단서 수치 비노출

- 단서 코드, 총 단서 수, 수집률을 사용자 UI에 표시하지 않는다.
- 내부 데이터의 증거 ID와 수집 상태는 저장, 검증, 디버깅을 위해 유지한다.
- 사용자는 자연어 기록명, 기록 분류, 발견 맥락으로 조사 정보를 이해한다.

### UI-DEC-005 상태값 표현

- `Trust`, `Public Anxiety`, `Evidence Integrity`의 내부 숫자와 판정 로직은 유지한다.
- 사용자 UI에는 숫자, 분수, 백분율, 상시 게이지를 표시하지 않는다.
- 필요한 순간에만 다음과 같은 문맥형 자연어를 표시한다.
  - `마커스는 경계하고 있다`
  - `선내 분위기: 불안`
  - `현장이 일부 교란됨`
- 자연어 메시지는 상태 변화나 현재 행동 판단에 필요한 기간만 표시한다.

### UI-DEC-006 상시 숫자 상태 HUD 폐기

- 상단에 Day, Trust, 불안도, 현장 보존도 숫자와 게이지를 계속 표시하는 기존
  `Status HUD` 구성은 폐기 예정 UI로 분류한다.
- 마이그레이션이 끝날 때까지 관련 오브젝트와 에셋이 남아 있더라도 제품 UI의
  기준으로 사용하지 않는다.
- 탐색 중 상단에는 현재 목표와 필요한 전역 기능만 유지한다.

### UI-DEC-007 탐색 상호작용

- 탐색 화면에는 장소 배경 안에 전신 인물이 실제 공간의 원근과 바닥선에 맞게
  배치되어야 한다.
- 인물은 별도 하단 대화 버튼이 아니라 화면에 배치된 전신 자체를 클릭한다.
- 소품과 출입구도 배경 위 실제 대상 또는 그 대상에 정렬된 투명 상호작용 영역을
  클릭한다.

### UI-DEC-008 클릭 포인트 표시

- 기본 탐색 상태에서는 클릭 포인트 아이콘, 이름표, 윤곽선을 상시 노출하지 않는다.
- 마우스 호버, 키보드·게임패드 포커스, 접근성 탐색 모드에서만 대상 윤곽과 이름을
  표시한다.
- 접근성 모드는 탐색 가능 대상을 순서대로 이동하고 읽을 수 있어야 한다.

### UI-DEC-009 Theory Slots 제거

- `Theory Slots`, `theorySlots`, `activeTheories`를 현재 기능으로 사용하지 않는다.
- 활성 기획 문서, Goal 프롬프트, 구현 계획과 테스트 계획에서 관련 요구사항을
  제거한다.
- 레거시 원본의 문구는 원본 무결성을 위해 수정하지 않되 구현 근거로 사용하지 않는다.

### UI-DEC-010 우상단 전역 기능

- 지도, 조사 기록, 일시정지는 플레이 화면 우상단의 공통 전역 기능으로 정렬한다.
- 현재 화면이 해당 기능을 허용하지 않으면 숨기거나 비활성 상태와 이유를 제공한다.
- 설정은 일시정지 화면을 통해 진입하는 것을 기본으로 한다.

### UI-DEC-011 취소와 뒤로가기

- 취소와 뒤로가기는 좌상단 또는 좌하단에 둔다.
- 오버레이가 여러 겹 열렸을 때 취소 입력은 가장 위에 열린 패널 하나만 닫는다.
- 지도나 조사 기록을 닫으면 진입 전 화면과 카메라 상태로 돌아간다.

### UI-DEC-012 주요 행동

- 우하단에는 현재 화면에서 가장 중요한 행동 하나만 배치하는 것을 원칙으로 한다.
- 확인, 이동, 조사, 질문, 검증, 결론 확정 중 현재 문맥의 주 행동만 강조한다.
- 같은 중요도의 확인 버튼을 여러 개 병렬로 두어 행동 우선순위를 흐리지 않는다.

### UI-DEC-013 UI 상태 알림

- 새로운 기록 획득, 상태 변화, 목표 갱신 알림은 서로 겹치지 않게 순차 표시한다.
- 알림은 내부 코드나 수집률보다 플레이어가 다음 판단에 사용할 자연어 정보를
  우선한다.

## 기존 기준과의 충돌 정리

| 기존 기준 또는 구현 | 충돌 | 결정 |
|---|---|---|
| 타이틀의 새 게임·이어하기 분리 | 시작 흐름 중복 | `시작` 이후 저장 슬롯에서 분기 |
| 상단 숫자형 Trust·불안도·현장 보존도 HUD | 몰입 저하, 불필요한 수치 노출 | 폐기 예정 UI로 분류 |
| 단서 코드·총량·수집률 표시 | 조사 내용을 숫자로 소비하게 함 | 사용자 UI에서 숨김 |
| 하단 인물 대화 버튼 | 공간 속 인물과 상호작용이 분리됨 | 배경 전신 직접 클릭 |
| 상시 클릭 포인트와 이름표 | 배경 몰입과 관찰성 저하 | 호버·포커스·접근성 모드에서만 표시 |
| 지도·증거·설정의 임의 배치 | HUD와 겹치고 화면별 위치가 달라짐 | 지도·조사 기록·일시정지를 우상단에 통일 |
| 우측의 복수 주요 행동 | 다음 행동의 우선순위 불명확 | 우하단 주요 행동 하나 |
| Theory Slots 계획 및 테스트 | 현재 데이터 계약과 불일치 | 활성 문서와 테스트 계획에서 제거 |

## 문서 적용 규칙

- 향후 와이어프레임과 UI 계획은 이 결정 기록을 입력 기준으로 사용한다.
- 기존 문서를 수정할 때 삭제한 요구사항을 다른 이름의 숫자 HUD나 가설 슬롯으로
  다시 도입하지 않는다.
- 내부 상태 숫자를 제거하는 것이 아니라 사용자 표현만 자연어로 전환한다.
- 공식 원본 PDF와 XLSX는 이 결정 기록 적용을 위해 직접 덮어쓰지 않는다.
